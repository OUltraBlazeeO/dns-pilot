# DNS Pilot

Русскоязычный DNS-менеджер для Windows x64. Позволяет проверить один сайт через выбранный сервер, сравнить результаты нескольких DNS и изменить DNS конкретного сетевого адаптера.

## Запуск на ПК

1. Откройте папку проекта **DNS Pilot**, затем папку **dist/1.2.0**. Для архива из GitHub Actions откройте папку распаковки.
2. Дважды нажмите **DNS Pilot.exe**. Этот файл можно скопировать в другую папку или на другой ПК. Установка Python, активация и подписка для запуска не требуются.
3. Дождитесь сведений о сети в верхней части окна. Если Windows использует разные основные адаптеры для IPv4 и IPv6 или несколько маршрутов имеют одинаковый приоритет, откройте **Настройки сети** и выберите нужное подключение. На этом ПК Wi-Fi называется **Беспроводная сеть 2**.
4. На **Главной** введите адрес сайта, например `wikipedia.org`. Выберите DNS из списка или введите свой IP либо DoH URL в поле выбора. Нажмите **Проверить**.
5. В разделе **Проверка сайтов** дважды нажмите строку результата. Откроются адрес назначения, время DNS, TCP, TLS и HTTP, цепочка перенаправлений и причины ошибок. Кнопка **Скопировать** копирует текст выбранного измерения.

Обычный запуск выполняйте с правами пользователя. Диалог UAC появляется при подтверждённом изменении системного DNS. Целевые платформы — Windows 10 x64 версии 1809 и новее и Windows 11 x64. Сборка проверена на Windows 11. [Платформы Qt](https://doc.qt.io/qt-6/windows.html)

## Проверка сайтов и своих серверов

- Откройте **DNS-серверы → Добавить DNS**. Для обычного DNS введите название и основной IP, при необходимости добавьте резервный IP того же семейства. Для DoH выберите DNS-over-HTTPS, укажите HTTPS URL и при необходимости **bootstrap IP**.
- Нажмите **Проверить соединение**, чтобы отправить DNS-запрос для example.org непосредственно на каждый указанный адрес. Результат содержит протокол, длительность и ответ DNS или причину ошибки. Проверка доступна до сохранения. Кнопка **Сохранить** добавляет профиль в каталог. Для изменения или удаления выберите пользовательскую запись в таблице.
- В проверках и сравнении основной и резервный серверы доступны по отдельности. В **Настройки сети** выбор обычного профиля заполняет оба IP. Системные изменения выполняет отдельная кнопка **Применить…**. Сохранённые DoH URL доступны в блоке **Защищённый DNS Windows**.
- В **Проверка сайтов** введите домены или полные URL, по одному на строку. Домен без схемы проверяется по HTTPS. Полный URL сохраняет порт, путь и параметры запроса. Выберите серверы и запустите проверку.
- Обычные запросы A и AAAA отправляются непосредственно на выбранный IP, порт 53. При усечённом UDP-ответе запрос повторяется по TCP. При ответе CNAME клиент следует цепочке через тот же резолвер.
- DoH использует POST с бинарным DNS-сообщением и проверкой сертификата. У предустановленных DoH-серверов указан bootstrap IP. Для своего URL без bootstrap Windows выполняет начальное разрешение имени **самого DoH-сервера**. DoH согласует HTTP/2 или HTTP/1.1. При нескольких адресах имени endpoint клиент пробует альтернативы в пределах тайм-аута. Адрес bootstrap виден в подробностях. Для сети только с IPv6 можно указать собственный DoH-сервер с IPv6 bootstrap.
- Для сайта программа открывает сокет на числовой IP из DNS-ответа. TLS получает исходное доменное имя в SNI. HTTP GET передаёт это имя в Host. Из ответа читаются заголовки, загрузка страницы и выполнение JavaScript не требуются. Для каждого перенаправления запросы выполняются заново. При вводе числового IP этап DNS пропускается.
- HTTPS использует доверенные корни Windows и набор корневых сертификатов certifi. При ошибке сертификата подробности содержат ошибку TLS. Если один адрес недоступен, программа пробует следующий.
- Диагностика выполняется напрямую. При обязательном корпоративном HTTP-прокси результат может отличаться от браузера. VPN, фильтры и маршруты Windows продолжают действовать. Ответ 403 или 429 означает, что сервер ответил и ограничил доступ. Ответ 5xx означает ошибку сервера. Успешный DNS-ответ сам по себе подтверждает только разрешение имени.

В настройках можно разрешить локальные сервисы для диагностики собственной сети. По умолчанию соединения с локальными и служебными IP блокируются на каждом переходе. Адрес самого DNS задаётся отдельно. Переход HTTPS → HTTP блокируется по умолчанию. В разрешённом режиме он помечается предупреждением и исключается из успешных защищённых проверок. Расширенная диагностика сохраняет тип содержимого, количество прочитанных байтов и конечный URL. Предел чтения тела составляет 16 КиБ.

## Сравнение и рекомендация

В **Сравнение DNS** укажите сайты, выберите от 2 до 20 DNS и при необходимости нажмите **Обязательные сайты**. Запустите **Подобрать лучший DNS**. В таблице для каждого сайта показаны две доли — успешное получение адресов и успешный конечный HTTPS-ответ. Двойной щелчок по ячейке показывает соответствующие измерения.

Для допуска к рекомендации нужен хотя бы один успешный HTTPS-результат. Каждый обязательный сайт должен пройти все повторы с DNS-разрешением и конечным HTTPS 2xx/3xx. Затем сравниваются число успешных проверок, доля запросов с ответом NOERROR и медиана времени DNS. При полном совпадении используется адрес DNS для воспроизводимого порядка. NOERROR с пустым AAAA считается корректным ответом на запрос, но сам по себе не даёт успешного соединения с сайтом. Медиана рассчитывается по успешным разрешениям, при нескольких переходах сначала берётся медиана внутри проверки.

Кнопка **Применить рекомендацию** показывает адаптер, семейство и будущий список DNS. При включённом в настройках автоприменении программа запрашивает согласие на одну серию с перечнем кандидатов. После тестов сравните прежние и новые адреса, медиану, долю успешных HTTPS и результаты обязательных сайтов. Подтвердите применение победителя или отмените его. Для виртуального адаптера требуется ещё одно согласие. Второй адрес можно задать вручную в настройках сети. При победе DoH настройка шифрования выполняется отдельно. Фонового периодического переключения DNS нет.

## Изменение и возврат DNS Windows

1. Откройте **Настройки сети**. Проверьте имя адаптера и текущие DNS обоих семейств. Выбор адаптера определяет, **где менять настройки**. Сетевые проверки следуют активной таблице маршрутов Windows.
2. Выберите IPv4 или IPv6. Введите основной и, при необходимости, резервный IP. В поле проверки укажите доступный вам сайт с доменным именем.
3. Нажмите **Применить…**, прочитайте предварительный просмотр и подтвердите действие. До запроса UAC приложение сохраняет исходное состояние и состояние перед текущей операцией. Отмена UAC оставляет прежнюю конфигурацию.
4. Windows получает изменение через `Set-DnsClientServerAddress` для CIM-объекта выбранного адаптера и семейства. Приложение повторно читает режим и адреса, проверяет домен через DnsQueryEx с индексом выбранного адаптера и обходом кеша, затем проверяет сайт через системный резолвер Windows. В этом тесте возможен системный кэш. Доступность сайта и совпадение сохранённых адресов являются отдельными проверками. [Команда Microsoft](https://learn.microsoft.com/en-us/powershell/module/dnsclient/set-dnsclientserveraddress)
5. При критической ошибке сетевой проверки можно подтвердить восстановление состояния непосредственно перед изменением. При прерывании операции или отказе в UAC во время восстановления откройте **Восстановление DNS…**. При следующем запуске появится такое же предложение. Сверьте адаптер и семейство. При изменении параметров извне программа попросит ручную сверку. **Вернуть предыдущие…** использует снимок до последней успешно завершённой операции. Для возврата первой сохранённой конфигурации выберите тот же адаптер и семейство, затем **Вернуть исходные настройки…**. Чтобы явно перейти на автоматическое получение DNS, выберите **Автоматически (DHCP)…**.

Оба семейства настраиваются отдельно. Исходный снимок привязан к GUID и семейству. Он содержит эффективные IPv4/IPv6-адреса, режимы назначения, сведения об адаптере и доступную информацию о DoH. При автоматическом назначении восстановление возвращает этот режим, поэтому полученные адреса могут зависеть от текущей сети.

Если режим назначения неизвестен, сведения о шифровании не читаются или на интерфейсе обнаружены индивидуальные параметры шифрования, приложение направляет в параметры Windows. Это ограничение текущего механизма изменения и восстановления DNS. Маршруты, прокси, VPN, системные политики и индивидуальные шаблоны шифрования программа не редактирует.

## DoH Windows и браузеров

В **Настройки сети → Защищённый DNS Windows** выберите провайдера, скопируйте шаблон и откройте параметры сети. В Windows 11 откройте свойства нужного подключения и изменение назначения DNS. Введите IP, включите DNS через HTTPS и при необходимости вставьте ручной шаблон. Выберите допустимость перехода на незашифрованный DNS по своим требованиям и сохраните параметры в Windows. Приложение показывает системный транспорт как неподтверждённый, когда фактическое шифрование запроса неизвестно. Windows 10 поддерживает DoH внутри DNS Pilot и совместимых браузеров. [Сетевые параметры Windows](https://support.microsoft.com/en-gb/windows/experience/connectivity-networking/essential-network-settings-and-tasks-in-windows)

В **Браузеры** выберите Edge, Chrome, Firefox или Brave, затем провайдера. Скопируйте DoH URL и откройте страницу настроек. Если браузер открыл начальную вкладку, вставьте отображаемый внутренний адрес настройки в адресную строку вручную. Выберите собственного провайдера и вставьте шаблон. Настройка браузера действует в его профиле независимо от системного DNS. [Firefox](https://support.mozilla.org/en-US/kb/dns-over-https) · [Chrome](https://support.google.com/chrome/answer/10468685) · [Edge](https://learn.microsoft.com/en-us/legal/microsoft-edge/privacy)

Предустановлены Cloudflare, Cloudflare Families с фильтрацией вредоносных доменов, Google Public DNS и Quad9. У каждого профиля есть основные и резервные IPv4/IPv6 и отдельный DoH endpoint. [Cloudflare](https://developers.cloudflare.com/1.1.1.1/infrastructure/network-operators/) · [Google IP](https://developers.google.com/speed/public-dns/docs/using/) · [Google DoH](https://developers.google.com/speed/public-dns/docs/doh) · [Quad9](https://docs.quad9.net/services/)

## Локальные данные

В **Настройки приложения → Оформление** выберите миниатюру Dark Utility, Aurora Glass, Editorial / Coral или Network Lab. Выбор сразу применяется и сохраняется. На главной странице график использует реальные измерения для последней пары сайт–DNS. При уменьшении ширины окна панели выстраиваются в одну колонку.

Вставьте `%LOCALAPPDATA%\DNS Pilot` в адресную строку Проводника. В этой папке хранятся:

| Файл | Содержимое |
|---|---|
| `settings.json` | Тема, тайм-ауты, повторы, список сайтов, пользовательские DNS, геометрия окна |
| `history.db` | История проверок, включая URL с замаскированной строкой запроса и этапы соединения |
| `backups` | Исходные и предыдущие конфигурации адаптеров |
| `pilot.log` | Ошибки приложения и, при включении подробного журнала, технические результаты |

**История** показывает последние 500 записей. Экспорт CSV или JSON включает всю сохранённую историю. Кнопка очистки удаляет результаты из базы. В **Настройки приложения** можно отключить новые записи, включить подробный вывод, изменить тайм-ауты, параллелизм и семейство адресов назначения. Изменения вступают в силу после **Сохранить настройки**. Максимум по умолчанию составляет 2000 записей. Новые технические результаты записываются в журнал только при включённых истории и подробном выводе. Старые журналы 1.1 и ранее экспортированные файлы могут содержать исходные URL. Сохранённые вручную сайты по умолчанию и DoH-профили содержат введённые адреса для повторного использования. Телеметрия отсутствует.

## Запуск из исходников и сборка

Для разработки нужен Python x64 3.12–3.14. Эта сборка использует Python 3.14.4, PySide6 Essentials 6.12, dnspython 2.9.2, h11 0.16 и PyInstaller 6.22.3. h11 обрабатывает HTTP/1.1 поверх уже открытого сокета, сохраняя контроль над IP назначения. Первый запуск установки зависимостей требует доступа к PyPI.

Откройте PowerShell **в папке проекта**.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe main.py
```

Для полной сборки выполните:

```powershell
.\build.ps1
```

Скрипт создаёт окружение при необходимости, устанавливает версии из файлов требований, выполняет pytest, собирает один оконный x64 EXE и запускает его автономную самопроверку. Результат — `dist\1.2.0\DNS Pilot.exe`. При уже установленных зависимостях используйте `.\build.ps1 -SkipInstall`. Путь к интерпретатору для создания окружения можно указать через `-Python`. В проект включён workflow GitHub Actions для сборки Windows-артефакта.

Сетевое ядро находится в `app/diagnostics.py` и `app/transport.py`, управление адаптерами и снимками — в `app/windows.py`, хранение — в `app/storage.py`. Окно и компоненты Qt находятся в `app/ui.py` и `app/widgets.py`, фоновые задания и системная проверка — в `app/desktop.py`.

## Проверка выпуска

Результаты текущей ревизии доступны в GitHub Actions. Версия 1.2 добавляет проверки аварийных фаз, редиректов, безопасных адресов, лимита тела, HTTP/2 и сохранности снимков. Проверены запуск готового EXE, чтение реальных адаптеров и внешняя диагностика. Прямые проверки получили HTTP 200 от dns.google через UDP и от github.com и example.org через DoH. Отдельная проверка через системный резолвер Windows получила HTTP 200 от GitHub. Для тестов записи настройки адаптера хранились в изолированной фикстуре. Запуск на Windows 10 и применение с UAC на тестовом адаптере остаются ручными интеграционными проверками. [Сценарии и команды проверки](MANUAL-TESTS.md)
