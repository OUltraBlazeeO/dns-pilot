# DNS Pilot 1.2.0

## Диагностика

- Прямой DoH поддерживает HTTP/2 и HTTP/1.1. Адрес соединения фиксируется, имя для TLS и HTTP сохраняется. При системном bootstrap повторяются попытки с другими IP.
- Международные домены преобразуются по UTS #46. Для каждого перехода видны конечный URL и предупреждения. Локальные назначения и переход HTTPS → HTTP по умолчанию блокируются. Расширенный режим читает до 16 КиБ тела ответа.
- Пакетная проверка ограничивает число фоновых заданий. У проверки сайта есть общий предел времени. Отмена ожидания системного резолвера освобождает задание интерфейса.

## Настройки Windows

- До UAC сохраняются исходная конфигурация и отдельный журнал текущей операции. Предыдущая точка отката обновляется после успешной проверки. После прерывания приложение предлагает восстановление.
- Новые снимки содержат SHA-256. Существующие копии 1.1 читаются с проверкой структуры. Контрольная сумма помогает выявить повреждение файла.
- Windows подтверждает конфигурацию повторным чтением. Дополнительно проверяются разрешение через индекс выбранного интерфейса без кеша и соединение через системный резолвер.
- Подбор требует итогового согласия. Для виртуального подключения требуется отдельное подтверждение. Равный результат исключает автоприменение. Изменение условий сравнения аннулирует рекомендацию.

## Пользовательские данные и поставка

- Параметры запросов маскируются в истории, экспортируемых результатах и журналах. В настройках доступны ограничение числа записей и отключение истории. Повреждённая база сохраняется для ручного восстановления.
- Сохранены четыре темы. На компактных экранах группы действий располагаются вертикально. DNS IPv4 и IPv6 показываются раздельно.
- Windows-артефакт содержит версионированный EXE, SHA256SUMS.txt и руководство. Для CPython 3.14 x64 зависимости сборки закреплены с хешами. CI выполняет статическую проверку, локальные сетевые тесты и запуск готового EXE.

## Настройка GitHub владельцем

Для main можно создать активный branch ruleset в Settings → Rules → Rulesets. Выберите ветку main, включите запрет удаления и force push, затем обязательные успешные проверки quality и build после их первого запуска. Если изменения должны проходить через PR, включите Require a pull request before merging. Для проекта с одним сопровождающим оставьте число обязательных сторонних одобрений равным нулю, если владелец не выбирает другой порядок. Отдельно согласуйте список исключений и проверьте его на тестовой ветке. Эти настройки и публикация тега выполняются владельцем по отдельному решению.
